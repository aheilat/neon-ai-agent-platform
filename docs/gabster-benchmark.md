# Gabster benchmark and Neon adaptation

## Reference snapshot

تمت مراجعة صفحات Gabster الرسمية في 14 أغسطس 2026. تصف Gabster نفسها كمنصة موحّدة لخدمة العملاء والمبيعات والتسويق، وتجمع القنوات في صندوق وارد واحد، وتدرّب الوكيل على الموقع والوثائق والأسئلة الشائعة، ثم تطلقه مع تسليم ذكي للموظفين. تُظهر الصفحة الرئيسية أيضاً مساراً من ثلاث مراحل: ربط القنوات، تدريب الوكيل، ثم الإطلاق والتوسع.

| المجال | ما تعرضه Gabster | التكييف المقترح في Neon |
|---|---|---|
| مصادر المعرفة | الموقع، الوثائق، الأسئلة الشائعة، وسجل المحادثات | إدخال رابط موقع العميل، زحف محدود وآمن، استخراج صفحات الخدمات وFAQ، ثم مراجعة المستخدم قبل الحفظ |
| فهم النشاط | تعلّم القطاع والمنتجات ونبرة العلامة التجارية | تقرير أولي يحدد اسم النشاط، وصفه، الخدمات، الجمهور، اللغة، النبرة، الأسئلة المتوقعة، ونقاط التصعيد |
| القنوات | WhatsApp، TikTok، Instagram، Messenger، Telegram، البريد، الدردشة، والصوت | إبقاء قنوات Neon الحالية مع اقتراح القنوات بناءً على إشارات الموقع، وإجبار المستخدم على تأكيدها قبل الربط |
| المحرك | تصنيف النية، استخراج الكيانات، فهم السياق، كشف المشاعر، وتسليم بشري | حفظ مخرجات التحليل كـ persona، goals، knowledge items، وhandoff rules، مع إبقاء الردود الطبية والمالية وغيرها ضمن حدود آمنة |
| العمليات | حجز، توجيه، متابعة، تحديث CRM، وأتمتة متعددة الخطوات | المرحلة التالية: إجراءات قابلة للمراجعة مثل حجز موعد، جمع lead، تحويل للفريق، ثم سجل تدقيق |
| الأمان | guardrails، موافقات، إخفاء PII، وسجلات تدقيق | منع جلب البيانات الحساسة، عدم تنفيذ أي إجراء خارجي أثناء التحليل، وعرض مصادر كل معلومة للمستخدم |
| الهاتف المحمول | تطبيق iOS وAndroid للرسائل والتنبيهات والتشغيل اليومي، مع بقاء إعدادات الوكيل المتقدمة على الويب | البدء بواجهة responsive/PWA، ثم تطبيق Expo منفصل يستهلك نفس API عند جاهزية الحسابات والمتاجر |

## Proposed Neon onboarding flow

1. **اكتشف نشاطك:** يضع العميل رابط موقعه، ويؤكد أن لديه صلاحية تحليل المحتوى العام.
2. **حلّل الموقع:** يجلب الخادم الصفحة الرئيسية وبعض الروابط الداخلية المسموح بها، ينظف HTML، ويستخرج العنوان والوصف والعناوين والفقرات والروابط.
3. **راجع ملخص النشاط:** يعرض النظام الخدمات المقترحة، الجمهور، اللغة، النبرة، الأسئلة المتوقعة، وقنوات مقترحة مع نسبة ثقة ومصادر الصفحات.
4. **عدّل قبل الحفظ:** يستطيع العميل حذف خدمة أو تعديل الوصف أو تحديد أهداف الوكيل وقنواته.
5. **أنشئ الوكيل:** يحفظ الخادم persona وdecision rules وknowledge items، مع وسم المصدر URL وتاريخ التحليل.
6. **اختبر مباشرة:** يفتح العميل live preview بأسئلة من الخدمات المستخرجة، ثم ينشئ الوكيل النهائي.

## Safety and operational limits

لا يجوز اعتبار محتوى الموقع حقيقة موثوقة تلقائياً. يجب تسجيل المصدر، توقيت الجلب، وحالة المراجعة. لا يُسمح للزاحف بتجاوز robots.txt أو تسجيل الدخول أو إرسال نماذج أو تنفيذ شراء أو حجز. يجب تحديد حد أقصى لعدد الصفحات وحجم النص ووقت الطلب، وحظر عناوين الشبكات الداخلية لتقليل مخاطر SSRF. أي قناة أو إجراء خارجي يبقى غير نشط حتى يوافق المستخدم ويربط بيانات الاعتماد.
