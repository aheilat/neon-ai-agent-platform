# Public Workflow Reference: Gabster

**Source reviewed:** `https://gabster.ai/en` on 25 August 2026.  
**Use:** Product-workflow reference only. This document does not authorize copying Gabster branding, content, visual design, source code, proprietary flows, or customer material.

## Publicly stated workflow

Gabster presents a three-step business journey: connect communication channels, train an AI agent from company materials, and go live with human handoff and ongoing improvement. Its public navigation groups the product around an AI chatbot, omnichannel/unified inbox, AI voice, automation, analytics, integrations, appointments, industries, and a mobile application.

| Public workflow capability | Independent Neon equivalent to build and verify |
|---|---|
| Create an initial agent | Register, create a tenant-scoped company agent, then display a clear agent setup home |
| Train from docs, site, and FAQs | Analyze a public website; upload supported files/images; show a verified knowledge list for the selected agent |
| Connect channels | Show available channel connections with an honest disabled state while Meta is inactive; do not present WhatsApp as live before approval |
| Test before launch | Provide a tenant-scoped chat preview and embeddable widget preview bound to the selected agent |
| Go live and hand off | Persist conversations, allow human handoff with consent and company-owned contact details, and support explicit close-out |
| Operate over time | Provide an independent conversation list, agent status, and later tenant-scoped team/notification/analytics modules |

## Neon implementation boundary

Neon will implement its own RTL-friendly interface, names, components, copy, information architecture, and independently owned code. The product will reuse only general software concepts visible on a public page: guided agent setup, knowledge ingestion, preview, channel readiness, human handoff, and operating views.
